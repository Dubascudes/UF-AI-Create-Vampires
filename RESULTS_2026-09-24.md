The first run included two exceptionally slow 8-frame chunks (105.71 and 95.19 seconds) while the model compiled kernels. Subsequent 8-frame chunks took approximately 0.26 seconds each in the server log. The warmed end-to-end output rate is below the upstream model-side 30 fps claim, and its roughly 0.4-second delay is large enough to be noticeable in a mirror.

Visual inspection of the first, middle, and last sampled output frames showed the people removed while the table, dishes, glasses, and chairs remained. The scene is not perfectly stable: some objects drift or morph, and a possible partial figure appears at the far right of a later frame. This clip does not test the intended handheld-object “floating” behavior, and no live webcam session has been evaluated yet.

The RTX run was faster after warmup but visually weaker: a person remained clearly visible in its sampled middle frame. A separate B200 run using a longer, more explicit empty-room prompt (`runs/b200-explicit-prompt-43208886/`) retained all three people in sampled frames. The default browser instruction therefore matches the shorter prompt used in the successful B200 runs. Prompt sensitivity and incomplete removal are material limitations; no configuration here guarantees the absence of people.

## Local YOLO person-mask trial, later on 2026-09-24

The active hybrid browser now offers local YOLO26n-seg in addition to MediaPipe Selfie Segmenter. The local checkpoint is `models/yolo26n-seg.pt` (6,719,965 bytes), used with Ultralytics 8.4.161, PyTorch 2.6.0+cu124, and an NVIDIA GeForce RTX 4070 Ti SUPER. The local service returns only class-0 person instance masks, merged into one binary mask. This is a person-mask test, not a generated-mirror throughput result.

One 640×480 webcam frame produced a nonempty mask covering 57.2% of the image. The saved `runs/local-yolo-webcam-overlay.png` shows the visible head, torso, and arms covered; the hands are not clearly exposed enough in that frame to judge the user's hand-edge concern. Its service-reported first person-frame model time was 93.9 ms, including one-time work not representative of steady state.

A separate 416×240 webcam frame was submitted 12 times to the already running local service. Omitting the first two requests, median model call time was **4.2 ms** and median local HTTP round-trip was **5.7 ms** across the remaining ten. The returned mask covered 59.5% of that frame. This repeated-frame timing does not measure changing-video throughput, browser compositing, JoyAI generation, or total mirror delay.

The integrated mirror was then run in Chrome with YOLO masks sent as reduced RGBA frames over a persistent local WebSocket and JoyAI output from the B200 endpoint on port 8083. The 1248×720 profile briefly showed **9–11 displayed fps**, **0.8–1.1 s capture-to-display delay**, and about **40–67 ms** of reported browser output work per displayed frame. A second run used the 840×480, 24-fps browser profile with the same B200 endpoint; it showed **10–12 displayed fps**, **0.84–0.91 s delay**, and about **50–55 ms** of output work. These are a few live UI snapshots, not a sustained benchmark or matched comparison with MediaPipe. The model packet counter was about 11–16 fps in those snapshots, so the remaining gap cannot be attributed solely to YOLO inference. The room was empty in the inspected output; raised hands, a turned body, and a held object still need a controlled visual comparison. The trials were stopped after inspection.
